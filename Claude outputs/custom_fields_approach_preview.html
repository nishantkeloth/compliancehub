Custom fields
Trade-off: no migration to add a field — an admin does it themselves in Org Settings, live. In exchange: values live in one JSONB blob (custom_fields->>'issuing_authority' instead of a plain column), so filtering/sorting the matrix on a custom field needs a JSONB index to stay fast, and every custom field needs this generic renderer rather than a hand-built input.

Typed columns — best when

  • The attribute set is dictated by the domain (maritime/HSE compliance), not by each customer
  • You want every field validated, sortable, exportable with zero extra work
  • New attributes are occasional, not a self-serve customer expectation

JSONB custom fields — best when

  • Different customer orgs genuinely need different tracked attributes
  • You want admins to self-serve new fields without engineering
  • You're prepared to build (and maintain) the generic field renderer once
